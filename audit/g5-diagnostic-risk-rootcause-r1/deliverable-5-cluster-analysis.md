## 共同根因(跨 run)

1. 缺陷 (a) 的根因单一:**插件 DIAG 正则(8 关键词)不覆盖无关键词失败返回**。三个 run 的
   目标文件同属"重试循环 + 失败返回"代码族(`const defaults = { retries: 2, ... }` × 4 函数),
   同一生成器产出同构代码 ⇒ 同一正则盲区以同一形态出现在全部 3 个 run。
2. 缺陷 (b) 的根因单一:**插件 marker 使用原始工具输出行号**(HEAD+1..n-TAIL),而 head/tail
   显示内容行号(envelope 偏移 3)。插件代码唯一 ⇒ 3 个 run 的 marker 全部继承同一缺陷。
3. 模型检出差异也与 run 无关(A/B 在三个 run 的行为模式一致)⇒ 分歧由机制 + 标准歧义驱动,
   **不是** run 特异性。

## 结论

- 3 个 run 呈现**完全同型**的缺陷结构:这不是 3 个独立问题,而是 1 个机制(插件 v1)在
  3 次执行中的确定性重现。
- 任务级正确表述:**3 个底层 case 的 30 个视图 100% 含缺陷 (a)(每视图 4 行)与缺陷 (b);
  12 条唯一缺陷行 + 1 个坐标系缺陷点,全部可归因到插件单一实现。**
- 任何"任务级成功率/安全率"都必须以 case=3 为分母,本轮视图级 30 不得用于此类计算。
